_13 juillet 2024._

## Prérequis et compatibilité

* **Crystal :** 1.11, 1.12 et 1.13.
* **Bases de données :**
  * MariaDB 10.4 et supérieur.
  * MySQL 8.0.11 et supérieur.
  * PostgreSQL 12 et supérieur.
  * SQLite 3.27.0 et supérieur.

## Nouvelles fonctionnalités

### Pré-chargement des relations

Marten offre désormais la possibilité de pré-charger les relations lors de l'utilisation des [query sets](../../models-and-databases/queries.md) grâce à la nouvelle méthode [`#prefetch`](../../models-and-databases/reference/query-set.md#prefetch). Lors de l'utilisation de [`#prefetch`](../../models-and-databases/reference/query-set.md#prefetch), les enregistrements correspondant aux relations spécifiées seront pré-chargés en lots uniques et chaque enregistrement retourné par le query set original aura les objets liés correspondants déjà sélectionnés et peuplés.

Par exemple :

```crystal
posts_1 = Post.all.to_a
# hits the database to retrieve the related "tags" (many-to-many relation)
puts posts_1[0].tags.to_a

posts_2 = Post.all.prefetch(:tags).to_a
# doesn't hit the database since the related "tags" relation was already prefetched
puts posts_2[0].tags.to_a
```

Comme la méthode existante [`#join`](../../models-and-databases/reference/query-set.md#join), cela permet d'atténuer les problèmes N+1 couramment rencontrés lors de l'accès aux objets liés. Cependant, contrairement à [`#join`](../../models-and-databases/reference/query-set.md#join) (qui ne peut être utilisé qu'avec des relations à valeur unique), [`#prefetch`](../../models-and-databases/reference/query-set.md#prefetch) peut être utilisé avec les relations à valeur unique et les relations à valeurs multiples (telles que les relations [many-to-many](../../models-and-databases/relationships.md#many-to-many-relationships), les relations [many-to-many inverses](../../models-and-databases/relationships.md#backward-relations-2) et les relations [many-to-one inverses](../../models-and-databases/relationships.md#backward-relations)).

Veuillez consulter [Pré-chargement des relations](../../models-and-databases/queries.md#pre-fetching-relations) pour en savoir plus sur cette nouvelle capacité.

### Scopes de modèle

Il est désormais possible de définir des [scopes](../../models-and-databases/queries.md#scopes) dans les classes de modèle. Les scopes permettent de pré-définir des query sets filtrés spécifiques, qui peuvent être facilement appliqués aux classes de modèle et aux query sets de modèle.

Ces scopes peuvent être définis via la macro [`#scope`](pathname:///api/0.5/Marten/DB/Model/Querying.html#scope(name%2C%26block)-macro), qui attend un nom de scope (littéral de chaîne ou symbole) comme premier argument et nécessite un bloc où la logique de filtrage du query set est définie :

```crystal
class Post < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :title, :string, max_size: 255
  field :is_published, :bool, default: false
  field :created_at, :date_time

  // highlight-next-line
  scope :published { filter(is_published: true) }
  // highlight-next-line
  scope :unpublished { filter(is_published: false) }
  // highlight-next-line
  scope :recent { filter(created_at__gt: 1.year.ago) }
end

Post.published # => Post::QuerySet [...]>
```

Il est également possible de surcharger le scope par défaut via la macro [`#default_scope`](pathname:///api/0.5/Marten/DB/Model/Querying.html#default_scope-macro). Cette macro nécessite un bloc où la logique de filtrage du query set est définie :

```crystal
class Post < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :title, :string, max_size: 255
  field :is_published, :bool, default: false
  field :created_at, :date_time

  // highlight-next-line
  default_scope { filter(is_published: true) }
end
```

Veuillez consulter [Scopes](../../models-and-databases/queries.md#scopes) pour plus de détails sur la définition des scopes.

### Champ enum pour les modèles et les schemas

Il est désormais possible de définir des champs `enum` dans les [modèles](../../models-and-databases/reference/fields.md#enum) et les [schemas](../../schemas/reference/fields.md#enum). Pour les modèles, ces champs permettent de stocker des valeurs enum valides, avec une validation appliquée au niveau de la base de données. Lors de la validation de données avec des schemas, ils permettent d'attendre des valeurs de chaîne valides correspondant à celles de l'enum configuré.

Par exemple :

```crystal
enum Category
  NEWS
  BLOG
end

class Article < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :category, :enum, values: Category
end

article = Article.last!
article.category # => Category::BLOG
```

### Filtrage par prédicats SQL bruts

Marten offre désormais la possibilité de filtrer les [query sets](../../models-and-databases/queries.md) en utilisant des [prédicats SQL bruts](../../models-and-databases/raw-sql.md#filtering-with-raw-sql-predicates) via la méthode `#filter`. Cela est utile lorsque vous souhaitez exploiter la flexibilité du SQL pour des conditions spécifiques, tout en laissant Marten gérer la sélection des colonnes et la construction de la requête pour le reste.

Par exemple :

```crystal
Author.filter("first_name = :first_name", first_name: "John")
Author.filter("first_name = ?", "John")
Author.filter { q("first_name = :first_name", first_name: "John") }
```

Veuillez consulter [Filtrage avec des prédicats SQL bruts](../../models-and-databases/raw-sql.md#filtering-with-raw-sql-predicates) pour en savoir plus sur cette nouvelle capacité.

### Fonctionnalités mineures

#### Modèles et bases de données

* Une nouvelle méthode [`#pks`](../../models-and-databases/reference/query-set.md#pks) a été introduite pour les query sets afin de faciliter la récupération des valeurs de clé primaire des enregistrements de modèle ciblés par un query set donné.
* Une méthode [`#count`](pathname:///api/0.5/Marten/DB/Model/Querying/ClassMethods.html#count(field%3AString|Symbol|Nil%3Dnil)-instance-method) est désormais disponible sur les classes de modèle et fournit la même fonctionnalité que la méthode de query set [`#count`](../../models-and-databases/reference/query-set.md#count).
* Une nouvelle méthode [`#bulk_create`](../../models-and-databases/reference/query-set.md#bulk_create) a été introduite pour faciliter l'insertion de plusieurs instances de modèle dans la base de données en une seule requête (ce qui peut être utile lorsqu'il s'agit de grandes quantités de données à insérer dans la base de données).
* Une nouvelle méthode [`#average`](../../models-and-databases/reference/query-set.md#average) a été introduite pour permettre de calculer les valeurs moyennes d'un champ de modèle spécifique au niveau de la base de données pour les enregistrements ciblés par un query set spécifique.
* Une nouvelle méthode [`#sum`](../../models-and-databases/reference/query-set.md#sum) a été introduite pour permettre de calculer la somme des valeurs d'un champ de modèle spécifique au niveau de la base de données pour les enregistrements ciblés par un query set spécifique.
* Il est désormais possible de calculer les valeurs minimale et maximale d'un champ spécifique au niveau de la base de données pour les enregistrements ciblés par un query set via les méthodes [`#minimum`](../../models-and-databases/reference/query-set.md#minimum) et [`#maximum`](../../models-and-databases/reference/query-set.md#maximum).
* Le prédicat de query set [`in`](../../models-and-databases/reference/query-set.md#in) prend désormais en charge le filtrage sur des tableaux d'enregistrements de modèle directement.
* Les query sets fournissent désormais une méthode [`#to_sql`](../../models-and-databases/reference/query-set.md#to_sql) permettant de récupérer la représentation SQL correspondante.
* Les query sets peuvent désormais être combinés en utilisant les opérateurs binaires ET et OU. Cela peut être réalisé via les méthodes de query set [&](../../models-and-databases/reference/query-set.md#-and) et [`|`](../../models-and-databases/reference/query-set.md#-or).
* Les exceptions d'enregistrement invalide (instances de [`Marten::DB::Errors::InvalidRecord`](pathname:///api/0.5/Marten/DB/Errors/InvalidRecord.html)) fournissent désormais plus de détails concernant les erreurs réelles de l'enregistrement associé.
* Les créations d'enregistrements à partir de query sets de relations inverses many-to-one sont désormais limitées à l'enregistrement lié. Consultez [Relations many-to-one](../../models-and-databases/relationships.md#many-to-one-relationships) pour plus de détails.
* Une nouvelle méthode [`#build`](../../models-and-databases/reference/query-set.md#build) a été introduite pour permettre d'initialiser de nouvelles instances de modèle à partir de query sets.

#### Handlers et HTTP

* La méthode d'aide [`#render`](../../handlers-and-http/introduction.md#render) et les handlers génériques impliquant des rendus de templates insèrent désormais automatiquement l'objet requête dans le contexte du template.
* Les handlers génériques [`Marten::Handlers::RecordDetail`](../../handlers-and-http/reference/generic-handlers.md#displaying-a-record), [`Marten::Handlers::RecordUpdate`](../../handlers-and-http/reference/generic-handlers.md#updating-a-record) et [`Marten::Handlers::RecordDelete`](../../handlers-and-http/reference/generic-handlers.md#deleting-a-record) offrent désormais la possibilité de spécifier un [query set](../../models-and-databases/queries.md) personnalisé au lieu d'une classe de modèle. Cela peut être réalisé grâce à l'utilisation de la macro [`#queryset`](pathname:///api/0.5/Marten/Handlers/RecordRetrieving.html#queryset(queryset)-macro).
* Un nouveau middleware a été introduit pour faciliter le remplacement de la méthode des requêtes entrantes en se basant sur la valeur d'un paramètre ou d'un en-tête de requête spécifique : le [middleware de remplacement de méthode](../../handlers-and-http/reference/middlewares.md#method-override-middleware). Ce mécanisme est utile pour remplacer les méthodes HTTP dans les formulaires HTML qui ne prennent nativement en charge que les méthodes GET et POST. Un ensemble dédié de [paramètres](../../development/reference/settings.md#method-overriding-settings) est également disponible pour personnaliser facilement le comportement de ce middleware.
* La valeur de la directive max-age utilisée pour l'en-tête Cache-Control défini par le [middleware de distribution d'assets](../../handlers-and-http/reference/middlewares.md#asset-serving-middleware) peut désormais être configurée dans le paramètre [`assets.max_age`](../../development/reference/settings.md#max_age).
* Les sous-classes du handler générique [`Marten::Handlers::Template`](../../handlers-and-http/reference/generic-handlers.md#rendering-a-template) prennent désormais en charge une méthode de classe [`#content_type`](pathname:///api/0.5/Marten/Handlers/Rendering/ClassMethods.html#content_type(content_type%3AString|Nil)-instance-method) qui permet de configurer le type de contenu de la réponse (sauf indication contraire, le type de contenu sera par défaut `text/html`).

#### Templates

* Les valeurs enum peuvent désormais être utilisées dans les templates. Veuillez consulter [Utiliser les enums dans les contextes](../../templates/introduction.md#using-enums-in-contexts) pour en savoir plus sur cette capacité.
* La prise en charge des littéraux `nil`, `true` et `false` a été ajoutée au langage de templates Marten. Veuillez consulter [Valeurs littérales](../../templates/introduction.md#literal-values) pour plus de détails sur les littéraux pris en charge.
* Le tag de template [`assign`](../../templates/reference/tags.md#assign) prend désormais en charge un suffixe `unless assigned` qui permet de spécifier que l'assignation ne doit avoir lieu que si aucune variable du même nom n'est déjà présente dans le contexte du template.
* Le tag de template [`include`](../../templates/reference/tags.md#include) prend désormais en charge les suffixes `isolated` et `contextual` qui permettent de spécifier si les templates inclus doivent avoir accès aux variables du contexte extérieur. Sauf indication contraire, le comportement par défaut est contrôlé par le nouveau paramètre [`templates.isolated_inclusions`](../../development/reference/settings.md#isolated_inclusions).
* Un nouveau tag de template [`capture`](../../templates/reference/tags.md#capture) a été introduit pour permettre d'assigner facilement la sortie d'un bloc de code à une nouvelle variable.
* La sortie du tag de template [`csrf_token`](../../templates/reference/tags.md#csrf_token) peut désormais être redirigée vers une variable en utilisant le mot-clé `as`.
* La variable `loop`, qui est disponible lors de l'utilisation du tag de template [`for`](../../templates/reference/tags.md#for), prend désormais en charge les attributs `even?` et `odd?`.
* Un nouveau tag de template [`csrf_input`](../../templates/reference/tags.md#csrf_input) a été introduit pour faciliter l'insertion du jeton CSRF dans les formulaires HTML. Ce nouveau tag permet la génération d'un champ de formulaire caché contenant le jeton CSRF calculé pour la requête en cours.
* Un nouveau tag de template [`escape`](../../templates/reference/tags.md#escape) a été introduit pour permettre de désactiver/activer l'[auto-échappement](../../templates/introduction.md#auto-escaping) au sein d'un bloc.
* Un nouveau tag de template [`unless`](../../templates/reference/tags.md#unless) a été introduit pour fournir une manière alternative d'écrire des blocs de template conditionnels.

#### Développement

* La commande de gestion [`collectassets`](../../development/reference/management-commands.md#collectassets) offre désormais la possibilité de fingerprinter les assets collectés et de générer un manifeste JSON correspondant. Veuillez consulter [Manifestes d'assets et fingerprinting](../../assets/introduction.md#asset-manifests-and-fingerprinting) pour en savoir plus sur cette capacité.
* L'[application d'authentification](../../authentication/introduction.md) intégrée (qui peut être générée soit via la commande de gestion [`new`](../../development/reference/management-commands.md#new) soit via le générateur [`auth`](../../development/reference/generators.md#auth)) utilise désormais des requêtes POST lors de la déconnexion des utilisateurs.
* Une commande de gestion [`play`](../../development/reference/management-commands.md#play) a été introduite pour faciliter le démarrage d'un serveur Crystal playground initialisé pour le projet en cours et son ouverture dans le navigateur par défaut.
* La commande de gestion [`new`](../../development/reference/management-commands.md#new) peut désormais générer des structures de projet/application qui utilisent la version de développement de Marten lorsque l'option `--edge` (ou `-e`) est utilisée.
* Un nouveau paramètre [`trailing_slash`](../../development/reference/settings.md#trailing_slash) a été introduit pour configurer si une redirection HTTP permanente (301) doit être émise lorsqu'une URL entrante qui ne correspond à aucune des routes configurées se termine ou non par un slash.
* Une nouvelle option `--open` a été ajoutée à la commande de gestion [`serve`](../../development/reference/management-commands.md#serve) pour permettre d'ouvrir automatiquement le serveur de développement dans le navigateur par défaut.
* Les nouveaux projets créés via la commande de gestion [`new`](../../development/reference/management-commands.md#new) ont désormais le niveau de log debug activé en développement (voir [`log_level`](../../development/reference/settings.md#log_level)).

#### Sécurité

* Il est désormais possible de configurer la persistance du jeton [CSRF](../../security/csrf.md) dans le store de session. Cela peut être réalisé en définissant le paramètre [`use_session`](../../development/reference/settings.md#use_session) sur `true`.

## Changements rétro-incompatibles

### Handlers et HTTP

* Les handlers utilisant le handler générique [`Marten::Handlers::Schema`](pathname:///api/0.5/Marten/Handlers/Schema.html) (ou les schemas héritant de celui-ci, comme [`Marten::Handlers::RecordCreate`](pathname:///api/0.5/Marten/Handlers/RecordCreate.html) ou [`Marten::Handlers::RecordUpdate`](pathname:///api/0.5/Marten/Handlers/RecordUpdate.html)) retourneront désormais une réponse **422 Unprocessable Content** au lieu d'une réponse **200 OK** lors du traitement d'un schema invalide. Bien que cela n'ait aucune incidence sur les utilisateurs finaux, ce changement peut faire échouer certains specs si vous testiez le code de réponse des handlers qui traitent des données de schema invalides. La solution sera de remplacer `200` par `422` dans les specs impactés.
