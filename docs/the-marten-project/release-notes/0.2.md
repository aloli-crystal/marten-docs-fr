_11 février 2023._

## Prérequis et compatibilité

Crystal 1.6 et 1.7.

## Nouvelles fonctionnalités

### Authentification

Le framework offre désormais la possibilité de générer des projets avec un [système d'authentification intégré](../../authentication.mdx) qui gère les besoins de base en gestion des utilisateurs : connexion/déconnexion des utilisateurs, réinitialisation des mots de passe, etc. Cela peut être réalisé grâce à l'option `--with-auth` de la commande de gestion [`new`](../../development/reference/management-commands.md#new) :

```bash
marten new project myblog --with-auth
```

L'option `--with-auth` garantit qu'une [application](../../development/applications.md) `auth` est créée pour le projet généré dans le dossier `src/auth`. Cette application fait partie du projet créé et fournit les [modèles](../../models-and-databases.mdx), [handlers](../../handlers-and-http.mdx), [schemas](../../schemas.mdx), [emails](../../emailing.mdx) et [templates](../../templates.mdx) nécessaires permettant d'authentifier les utilisateurs avec des adresses email et des mots de passe, tout en prenant en charge les flux standard de réinitialisation de mot de passe. Toutes ces abstractions fournissent une implémentation d'authentification "par défaut" qui peut ensuite être mise à jour par projet pour mieux répondre aux exigences liées à l'authentification.

### Envoi d'emails

Marten vous permet désormais de définir des [emails](../../emailing.mdx) que vous pouvez entièrement personnaliser (propriétés, valeurs d'en-tête, etc.) et dont les corps (HTML et/ou texte) sont rendus en utilisant des [templates](../../templates.mdx). Par exemple, voici comment définir un email simple et comment le livrer :

```crystal
class WelcomeEmail < Marten::Email
  to @user.email
  subject "Hello!"
  template_name "emails/welcome_email.html"

  def initialize(@user : User)
  end
end

email = WelcomeEmail.new(user)
email.deliver
```

Les emails sont livrés en utilisant un [mécanisme de backend d'envoi d'emails](../../emailing/introduction.md#emailing-backends). Les backends d'envoi d'emails implémentent _la manière_ dont les emails sont réellement envoyés et livrés. Actuellement, Marten prend en charge un [backend d'envoi d'emails de développement](../../emailing/reference/backends.md#development-backend) intégré, ainsi qu'un ensemble d'autres [backends tiers](../../emailing/reference/backends.md#other-backends) que vous pouvez installer selon vos besoins d'envoi d'emails.

Veuillez consulter la [section Envoi d'emails](../../emailing.mdx) pour en savoir plus sur cette nouvelle fonctionnalité.

### Capacités SQL brut

Les query sets offrent désormais la possibilité d'effectuer des requêtes brutes qui sont mappées vers des instances de modèles réels. Cela est intéressant si les capacités fournies par les query sets ne sont pas suffisantes pour la tâche en question et que vous devez écrire des requêtes SQL personnalisées.

Par exemple :

```crystal
Article.raw("SELECT * FROM articles WHERE title = ?", "Hello World!").each do |article|
  # Do something with `article` record
end
```

Veuillez consulter [SQL brut](../../models-and-databases/raw-sql.md) pour en savoir plus sur cette capacité.

### Champ email pour les modèles et les schemas

Il est désormais possible de définir des champs `email` dans les [modèles](../../models-and-databases/reference/fields.md#email) et les [schemas](../../schemas/reference/fields.md#email). Ceux-ci vous permettent de persister facilement des adresses email valides dans vos modèles mais aussi d'attendre des adresses email valides dans les données validées via l'utilisation de schemas.

Par exemple :

```crystal
class User < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :email, :email, unique: true
end
```

### Callbacks de transaction

Les modèles prennent désormais en charge la définition de callbacks de transaction en utilisant les macros [`#after_commit`](../../models-and-databases/callbacks.md#after_commit) et [`#after_rollback`](../../models-and-databases/callbacks.md#after_rollback).

Par exemple :

```crystal
class User < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :username, :string, max_size: 64, unique: true

  after_commit :do_something, on: :update

  private def do_something
    # Do something!
  end
end
```

Veuillez consulter [Callbacks](../../models-and-databases/callbacks.md) pour en savoir plus sur cette capacité.

### Fonctionnalités mineures

#### Modèles et bases de données

* La prise en charge des [paramètres de pool de connexions DB](https://crystal-lang.org/reference/database/connection_pool.html) a été ajoutée. Consultez la [référence des paramètres de base de données](../../development/reference/settings.md#database-settings) pour plus de détails sur les paramètres pris en charge
* Les champs de modèle contribuent désormais des méthodes `#<fieldName>?` aux classes de modèle afin d'identifier facilement si un champ a une valeur ou non. Notez que cette capacité est également activée pour les méthodes de relation fournies par les champs [`many_to_one`](../../models-and-databases/reference/fields.md#many_to_one) et [`one_to_one`](../../models-and-databases/reference/fields.md#one_to_one)
* Il est désormais possible d'utiliser une macro [`#with_timestamp_fields`](https://martenframework.com/docs/api/0.2/Marten/DB/Model/Table.html#with_timestamp_fields-macro) pour créer automatiquement des champs d'horodatage `created_at` / `updated_at` dans les modèles. Le champ `created_at` est rempli avec l'heure actuelle lors de la création de nouveaux enregistrements tandis que le champ `updated_at` est actualisé avec l'heure actuelle chaque fois que les enregistrements sont mis à jour. Consultez [Horodatages](../../models-and-databases/introduction.md#timestamps) pour en savoir plus sur cette capacité
* Il est désormais possible de récupérer facilement des valeurs de colonnes spécifiques sans charger des objets d'enregistrement entiers en utilisant les méthodes de query set [`#pluck`](../../models-and-databases/reference/query-set.md#pluck) et [`#pick`](../../models-and-databases/reference/query-set.md#pick)

#### Handlers et HTTP

* `string` peut désormais être utilisé comme alias pour `str` lors de la définition de [paramètres de routage](../../handlers-and-http/routing.md#specifying-route-parameters)

#### Templates

* La prise en charge des recherches par index a été ajoutée. Cela signifie qu'il est désormais possible de récupérer des valeurs d'index spécifiques à partir d'objets indexables dans les templates en utilisant la syntaxe `{{ var.<index> }}` (par exemple : `{{ var.0 }}`)
* Un filtre de template [`linebreaks`](../../templates/reference/filters.md#linebreaks) a été introduit pour permettre de remplacer facilement tous les sauts de ligne par des sauts de ligne HTML (`<br />`) dans les chaînes

#### Schemas

* Les schemas peuvent désormais être initialisés à partir des paramètres de routage des handlers (ce qui signifie qu'ils peuvent être initialisés à partir des hashs retournés par la méthode [`Marten::Handlers::Base#params`](https://martenframework.com/docs/api/0.2/Marten/Handlers/Base.html#params%3AHash(String%2CInt16|Int32|Int64|Int8|String|UInt16|UInt32|UInt64|UInt8|UUID)-instance-method))

#### Commandes de gestion

* La commande de gestion [`serve`](../../development/reference/management-commands.md#serve) prend désormais en charge la possibilité de remplacer l'hôte et le port utilisés par le serveur de développement

#### Tests

* Un [client de test](../../development/testing.md#using-the-test-client) a été introduit afin de permettre aux développeurs de tester facilement les handlers (et les différentes routes d'un projet) en émettant des requêtes et en inspectant les réponses retournées.

## Changements rétro-incompatibles

### Templates

* Les variables de boucle for `loop.first` et `loop.last` ont été respectivement renommées `loop.first?` et `loop.last?`. Consultez la [référence des tags de template](../../templates/reference/tags.md#for) pour en savoir plus sur le tag de template `for`

### Commandes de gestion

* L'argument optionnel de répertoire de la commande de gestion [`new`](../../development/reference/management-commands.md#new) a été remplacé par une option dédiée `-d DIR, --dir=DIR`
