_3 août 2025._

## Prérequis et compatibilité

* **Crystal :** 1.15, 1.16 et 1.17.
* **Bases de données :**
  * MariaDB 10.5 et supérieur.
  * MySQL 8.0.11 et supérieur.
  * PostgreSQL 14 et supérieur.
  * SQLite 3.31.0 et supérieur.

## Nouvelles fonctionnalités

### Routes localisées

Marten offre désormais la possibilité de définir des routes localisées grâce à deux mécanismes : l'ajout automatique de préfixes de locale aux routes et l'activation de la locale appropriée en fonction du préfixe, et la traduction des routes elles-mêmes. Ces mécanismes peuvent être utilisés indépendamment ou en combinaison.

Par exemple, la map de routes suivante définit des routes qui seront préfixées par la locale actuellement activée et dont les chemins seront traduits en utilisant les traductions du projet considéré :

```crystal
ARTICLE_ROUTES = Marten::Routing::Map.draw do
  path t("routes.articles.list"), ArticlesHandler, name: "list"
  path t("routes.articles.create"), ArticleCreateHandler, name: "create"
  path t("routes.articles.detail"), ArticleDetailHandler, name: "detail"
  path t("routes.articles.update"), ArticleUpdateHandler, name: "update"
  path t("routes.articles.delete"), ArticleDeleteHandler, name: "delete"
end

Marten.routes.draw do
  localized do
    path t("routes.landing"), LandingPageHandler, name: "landing"
    path t("routes.articles.prefix"), ARTICLE_ROUTES, name: "articles"
  end
end
```

Comme illustré ci-dessus, l'utilisation de routes préfixées par des locales peut être activée en encapsulant les chemins de routes dans un appel à la méthode [`#localized`](https://martenframework.com/docs/api/0.6/Marten/Routing/Map.html#localized(prefix_default_locale%3Dtrue%2C%26)%3ANil-instance-method). Les traductions de chemins de routes peuvent être définies en utilisant la méthode [`#t`](https://martenframework.com/docs/api/0.6/Marten/Routing/Map.html#t(path%3AString)%3ATranslatedPath-instance-method), qui assigne une clé de traduction à chaque route (cette clé est ensuite utilisée dynamiquement pour générer le chemin de la route en fonction de la locale active).

Avec la map de routes définie ci-dessus, les routes générées sont entièrement localisées et varient en fonction de la locale actuellement activée :

```crystal

I18n.activate("en")
Marten.routes.reverse("landing")         # => "/en/landing"
Marten.routes.reverse("articles:create") # => "/en/articles/create"

I18n.activate("fr")
Marten.routes.reverse("landing")         # => "/fr/accueil"
Marten.routes.reverse("articles:create") # => "/fr/articles/creer"
```

Veuillez consulter [Routes localisées](../../i18n/localized-routes.md) pour en savoir plus sur cette nouvelle capacité.

### Annotations

Marten permet désormais d'annoter les query sets avec des données agrégées. Cela est utile lorsque vous avez besoin de "conserver" des valeurs agrégées pour chaque enregistrement d'un query set (éventuellement pour un filtrage ultérieur ou pour utiliser les valeurs agrégées lors du traitement des enregistrements individuels). Cela peut être réalisé en utilisant la méthode [`#annotate`](../../models-and-databases/reference/query-set.md#annotate).

Par exemple :

```crystal
# Annotate the query set with the number of articles for each author.
Author.all.annotate { count(:articles) }

# Get all the authors that have more than 10 articles.
Author.all.annotate { count(:articles) }.where(articles_count__gt: 10)

# Order all the authors by the number of articles they have.
Author.all.annotate { count(:articles) }.order(:articles_count)

# Access the annotated values for each author.
authors = Author.all.annotate { count(:articles) }
authors.each do |author|
  puts author.name
  puts author.annotations["articles_count"]
end
```

Veuillez consulter la section [Agrégations](../../models-and-databases/queries.md#aggregations) pour en savoir plus sur cette nouvelle capacité.

### Champ de schema tableau

Marten permet désormais de définir des champs de schema `array` qui permettent de valider des listes de valeurs, chaque valeur étant soumise aux règles de validation d'un champ membre du tableau (comme `string`, `int` ou tout autre [type de champ de schema](../../schemas/reference/fields.md) existant).

Par exemple, le schema suivant permet de valider des listes de valeurs de chaîne dont les tailles ne doivent pas dépasser 10 :

```crystal
class TestSchema < Marten::Schema
  field :values, of: :string, max_size: 10
end
```

Comme illustré par l'exemple ci-dessus, le type du champ membre sous-jacent du tableau doit être spécifié via l'option [`of`](../../schemas/reference/fields.md#of), qui doit référencer un [type de champ de schema existant](../../schemas/reference/fields.md#field-types) (comme `string`, `enum`, etc).

Veuillez consulter la [référence des champs de schema](../../schemas/reference/fields.md#array) pour en savoir plus sur les champs `array`.

### Champs image pour les modèles et les schemas

Il est désormais possible de définir des champs `image` dans les [modèles](../../models-and-databases/reference/fields.md#image) et les [schemas](../../schemas/reference/fields.md#image), qui vous permettent de stocker ou valider des fichiers qui sont effectivement des images. Cette capacité nécessite l'utilisation du shard [crystal-vips](https://github.com/naqvis/crystal-vips).

Par exemple :

```crystal
class ImageAttachment < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :uploaded_file, :image, blank: false, null: false
end

attachment = ImageAttachment.first!
attachment.uploaded_file            # => #<Marten::DB::Field::File::File:0x102dd0ac0 ...>
attachment.uploaded_file.attached?  # => true
attachment.uploaded_file.name       # => "test.png"
attachment.uploaded_file.size       # => 5796929
attachment.uploaded_file.url        # => "/media/test.png"
```

### Fonctionnalités mineures

#### Modèles et bases de données

* Les [query sets](../../models-and-databases/queries.md) prennent désormais en charge les opérations XOR lors de l'[exécution de requêtes complexes impliquant des expressions `q`](../../models-and-databases/queries.md#complex-filters-with-q-expressions). De plus, la combinaison de query sets en utilisant l'opérateur XOR (`^`) est désormais également prise en charge (voir [`#^ (XOR)`](../../models-and-databases/reference/query-set.md#-xor)).
* Une nouvelle option [`slugify`](../../models-and-databases/reference/fields.md#slugify) a été ajoutée aux champs de modèle [`slug`](../../models-and-databases/reference/fields.md#slug) afin de permettre de générer automatiquement une valeur slug à partir d'un autre champ local du modèle.
* Les pages de requête (instances de [`Marten::DB::Query::Page`](https://martenframework.com/docs/api/0.6/Marten/DB/Query/Page.html)) exposent désormais une méthode [`#pages_count`](https://martenframework.com/docs/api/0.6/Marten/DB/Query/Page.html#pages_count-instance-method) qui permet d'obtenir le nombre total de pages.
* Les objets liés sont désormais automatiquement chargés lors de l'accès aux relations inverses (comme les relations inverses many-to-one ou les relations inverses one-to-one).
* La possibilité de récupérer des enregistrements spécifiques en utilisant des prédicats SQL bruts a été introduite. Consultez [Récupérer des enregistrements uniques avec des prédicats SQL bruts](../../models-and-databases/raw-sql.md#fetching-single-records-with-raw-sql-predicates) pour en savoir plus sur cette nouvelle capacité.
* La méthode de query set [`#prefetch`](../../models-and-databases/reference/query-set.md#prefetch) fournit désormais un argument optionnel `query_set`, permettant de spécifier un query set personnalisé pour récupérer les enregistrements pré-chargés.
* Une nouvelle méthode `#total_count` a été ajoutée aux objets [paginator](https://martenframework.com/docs/api/0.6/Marten/DB/Query/Paginator.html#total_count%3AInt32|Int64-instance-method) et [page](https://martenframework.com/docs/api/0.6/Marten/DB/Query/Page.html#total_count-instance-method) pour permettre de récupérer le nombre total d'enregistrements dans le query set paginé, sans appliquer la pagination.

#### Handlers et HTTP

* Les [stores de session](../../handlers-and-http/sessions.md) permettent désormais de configurer facilement quand les entrées de session expirent grâce aux méthodes [`#expires_at=`](https://martenframework.com/docs/api/0.6/Marten/HTTP/Session/Store/Base.html#expires_at%3D(value%3ATime)-instance-method), [`#expires_at_browser_close=`](https://martenframework.com/docs/api/0.6/Marten/HTTP/Session/Store/Base.html#expires_at_browser_close%3D(value%3ABool)-instance-method) et [`#expires_in=`](https://martenframework.com/docs/api/0.6/Marten/HTTP/Session/Store/Base.html#expires_in%3D(value%3ATime%3A%3ASpan)-instance-method). Veuillez consulter [Personnaliser les temps d'expiration des sessions](../../handlers-and-http/sessions.md#customizing-session-expiry-times) pour en savoir plus sur cette capacité.
* Un alias pour la méthode de handler [`#reverse`](https://martenframework.com/docs/api/0.6/Marten/Handlers/Base.html#reverse(*args%2C**options)-instance-method) ([`#url`](https://martenframework.com/docs/api/0.6/Marten/Handlers/Base.html#url(name%3AString|Symbol%2C**kwargs)%3AString-instance-method)) a été introduit.
* Un [middleware Referrer-Policy](../../handlers-and-http/reference/middlewares.md#referrer-policy-middleware) a été introduit pour permettre de définir automatiquement l'en-tête Referrer-Policy dans les réponses générées par les handlers.
* Un nouveau paramètre [`unsupported_http_method_strategy`](../../development/reference/settings.md#unsupported_http_method_strategy) a été introduit pour permettre de configurer la stratégie à utiliser lors du traitement de méthodes HTTP non prises en charge dans les handlers. Ce paramètre peut être utilisé pour configurer si de telles requêtes doivent résulter en des réponses 405 Method Not Allowed (le comportement par défaut) ou des réponses 404 Not Found.
* Il est désormais possible d'utiliser n'importe quel hash ou tuple nommé pour définir les données initiales de schema dans les handlers qui utilisent des sous-classes de [`Marten::Handlers::Schema`](https://martenframework.com/docs/api/0.6/Marten/Handlers/Schema.html) (dans la méthode [`#initial_data`](https://martenframework.com/docs/api/0.6/Marten/Handlers/Schema.html#initial_data-instance-method)).
* Les exceptions de [résolution inverse d'URL](../../handlers-and-http/routing.md#reverse-url-resolutions) incorrectes intègrent désormais plus de détails concernant les paramètres manquants et invalides.
* La possibilité de définir des [callbacks de gestion d'exceptions spécifiques](../../handlers-and-http/introduction.md#exceptions-handling) avec la macro `#rescue_from` a été ajoutée aux handlers.
* Le handler générique [`Marten::Handlers::RecordCreate`](../../handlers-and-http/reference/generic-handlers.md#creating-a-record) définit désormais une méthode [`#save_record`](https://martenframework.com/docs/api/0.6/Marten/Handlers/RecordCreate.html#save_record%3ADB%3A%3AModel-instance-method) qui peut être surchargée afin de personnaliser la manière dont le nouvel enregistrement est sauvegardé à partir des données du schema validé.
* Le handler générique [`Marten::Handlers::RecordCreate`](../../handlers-and-http/reference/generic-handlers.md#creating-a-record) définit désormais une méthode [`#prepare_record_attributes`](https://martenframework.com/docs/api/0.6/Marten/Handlers/RecordCreate.html#prepare_record_attributes-instance-method) qui peut être surchargée afin de générer un hash d'attributs qui sera utilisé pour créer le nouvel enregistrement (ce hash contient par défaut les données du schema validé).
* Le handler générique [`Marten::Handlers::RecordUpdate`](../../handlers-and-http/reference/generic-handlers.md#updating-a-record) définit désormais une méthode [`#save_record`](https://martenframework.com/docs/api/0.6/Marten/Handlers/RecordUpdate.html#save_record%3ANil-instance-method) qui peut être surchargée afin de personnaliser la manière dont l'enregistrement est sauvegardé à partir des données du schema validé.
* Le handler générique [`Marten::Handlers::RecordUpdate`](../../handlers-and-http/reference/generic-handlers.md#updating-a-record) définit désormais une méthode [`#prepare_record_attributes`](https://martenframework.com/docs/api/0.6/Marten/Handlers/RecordUpdate.html#prepare_record_attributes-instance-method) qui peut être surchargée afin de générer un hash d'attributs qui sera utilisé pour mettre à jour l'enregistrement (ce hash contient par défaut les champs du schema validé qui correspondent aux champs du modèle).

#### Templates

* Un nouveau tag de template [`localize`](../../templates/reference/tags.md#localize) a été introduit pour faciliter la localisation de valeurs (comme les dates, les nombres et les valeurs de temps) au sein des templates.
* Un nouveau filtre de template [`underscore`](../../templates/reference/filters.md#underscore) a été introduit pour faciliter l'obtention de la version en underscore d'une chaîne au sein des templates.
* Un alias pour le tag de template [`url`](../../templates/reference/tags.md#url) ([`reverse`](../../templates/reference/tags.md#reverse)) a été introduit.
* Le tag de template [`for`](../../templates/reference/tags.md#for) expose désormais une variable `loop.length` pour permettre de récupérer le nombre total d'itérations dans la boucle.

#### Schemas

* Les champs de schema [`date`](../../schemas/reference/fields.md#date) et [`date_time`](../../schemas/reference/fields.md#date_time) se rabattent désormais sur les formats spécifiés dans les paramètres [`date_input_formats`](../../development/reference/settings.md#date_input_formats) et [`date_time_input_formats`](../../development/reference/settings.md#date_time_input_formats), respectivement, lorsque les formats localisés ne parviennent pas à parser les valeurs brutes des champs.

#### Développement

* Une nouvelle option de commande `--log-level` a été introduite pour faciliter la configuration du niveau de log à utiliser lors de l'exécution des [commandes de gestion](../../development/management-commands.md) (voir [Options partagées](../../development/management-commands.md#shared-options) pour plus de détails).
* La commande de gestion [`new`](../../development/reference/management-commands.md#new) permet désormais de générer des projets sans bases de données configurées lorsque l'option `--database=none` est utilisée.
* Les projets générés avec la commande de gestion [`new`](../../development/reference/management-commands.md#new) incluent désormais le [middleware Referrer-Policy](../../handlers-and-http/reference/middlewares.md#referrer-policy-middleware) par défaut.
* La commande de gestion [`new`](../../development/reference/management-commands.md#new) génère désormais un fichier `seed.cr` lors de la génération de nouvelles structures de projet.
* Une nouvelle commande de gestion [`seed`](../../development/reference/management-commands.md#seed) a été introduite pour faciliter l'exécution des fichiers de seed.
* Les entrées de log générées lors de l'exécution du serveur de développement (commande de gestion [`serve`](../../development/reference/management-commands.md#serve)) en mode debug incluent désormais plus de détails sur les requêtes traitées, les templates rendus et les requêtes SQL exécutées.
* La configuration de base de données prend désormais en charge les chaînes de connexion, ce qui peut être utile dans les scénarios où seule une chaîne de connexion est fournie (par ex. via une variable d'environnement `DATABASE_URL` provenant de fournisseurs cloud). Consultez les [paramètres de base de données](../../development/reference/settings.md#database-settings) pour en savoir plus sur cette nouvelle capacité.
* De nouveaux paramètres [`date_input_formats`](../../development/reference/settings.md#date_input_formats) et [`date_time_input_formats`](../../development/reference/settings.md#date_time_input_formats) ont été introduits pour offrir une flexibilité supplémentaire dans le parsing des valeurs de champs de schema [`date`](../../schemas/reference/fields.md#date) et [`date_time`](../../schemas/reference/fields.md#date_time). Ces paramètres permettent de définir des formats d'entrée de repli qui sont utilisés lorsque les formats localisés ne parviennent pas à parser les valeurs brutes des champs [`date`](../../schemas/reference/fields.md#date)/[`date_time`](../../schemas/reference/fields.md#date_time) de schema.
* La commande de gestion [`new`](../../development/reference/management-commands.md#new) fournit désormais une option `--with-image-support` afin de faciliter la génération de nouveaux projets avec la prise en charge des [champs image](../../models-and-databases/reference/fields.md#image).

#### Internationalisation

* Les traductions définies dans le dossier `config/locales` sont désormais chargées automatiquement par le framework si elles sont définies (voir [Définir les traductions](../../i18n/introduction.md#defining-translations) pour en savoir plus sur les emplacements depuis lesquels les traductions peuvent être chargées).
* Un nouveau paramètre [`i18n.fallbacks`](../../development/reference/settings.md#fallbacks) a été introduit pour permettre de configurer facilement les locales de repli.

## Changements rétro-incompatibles

### Internationalisation

* Les projets Marten utilisent désormais automatiquement par défaut une chaîne de locales de repli définie sur `["en"]`. Cela signifie que toutes les traductions manquantes pour une locale spécifique seront automatiquement renvoyées vers la locale `en` par défaut. Ce comportement peut être personnalisé en mettant à jour le paramètre [`i18n.fallbacks`](../../development/reference/settings.md#fallbacks).
