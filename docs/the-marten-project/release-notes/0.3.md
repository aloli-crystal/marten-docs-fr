_19 juin 2023._

## Prérequis et compatibilité

Crystal 1.6, 1.7 et 1.8.

## Nouvelles fonctionnalités

### Prise en charge des réponses en streaming

Il est désormais possible de générer facilement des réponses en streaming à partir d'itérateurs de chaînes en utilisant la classe [`Marten::HTTP::Response::Streaming`](pathname:///api/0.3/Marten/HTTP/Response/Streaming.html) ou la méthode d'aide [`#respond`](pathname:///api/0.3/Marten/Handlers/Base.html#respond(streamed_content%3AIterator(String)%2Ccontent_type%3DHTTP%3A%3AResponse%3A%3ADEFAULT_CONTENT_TYPE%2Cstatus%3D200)-instance-method). Cela peut être bénéfique si vous avez l'intention de générer des réponses longues ou des réponses qui consomment excessivement de la mémoire (un exemple classique est la génération de fichiers CSV volumineux).

Veuillez consulter [Réponses en streaming](../../handlers-and-http/introduction.md#streaming-responses) pour en savoir plus sur cette nouvelle capacité.

### Mise en cache

Marten vous permet désormais d'interagir avec un store de cache global qui permet d'interagir avec un système de cache sous-jacent et d'effectuer des opérations de base telles que la récupération d'entrées en cache, l'écriture de nouvelles entrées, etc. En utilisant la mise en cache, vous pouvez sauvegarder le résultat d'opérations coûteuses afin de ne pas avoir à les effectuer pour chaque requête.

Le cache global est accessible via la méthode [`Marten#cache`](pathname:///api/0.3/Marten.html#cache%3ACache%3A%3AStore%3A%3ABase-class-method). Voici quelques exemples montrant comment effectuer des opérations de mise en cache basiques :

```crystal
# Fetching an entry from the cache.
Marten.cache.fetch("mykey", expires_in: 4.hours) do
  "myvalue"
end

# Reading from the cache.
Marten.cache.read("unknown") # => nil
Marten.cache.read("mykey") # => "myvalue"
Marten.cache.exists?("mykey") => true

# Writing to the cache.
Marten.cache.write("foo", "bar", expires_in: 10.minutes) => true
```

La mise en cache de Marten s'appuie sur un [mécanisme de store de cache](../../caching/introduction.md#configuration-and-cache-stores). Par défaut, Marten utilise un cache en mémoire (instance de [`Marten::Cache::Store::Memory`](pathname:///api/0.3/Marten/Cache/Store/Memory.html)) et d'autres [stores tiers](../../caching/reference/stores.md#other-stores) peuvent être installés selon vos besoins de mise en cache (par ex. Memcached, Redis).

Les nouvelles capacités de mise en cache de Marten ne se limitent pas à sa fonctionnalité de cache standard. Elles peuvent également être utilisées efficacement via la nouvelle fonctionnalité de [mise en cache de fragments de templates](../../caching/introduction.md#template-fragment-caching), rendue possible par le tag de template [`cache`](../../templates/reference/tags.md#cache). Avec cette fonctionnalité, des parties spécifiques de vos [templates](../../templates.mdx) peuvent désormais être mises en cache facilement.

Veuillez consulter la section [Mise en cache](../../caching.mdx) pour en savoir plus sur ces nouvelles capacités.

### Champ JSON pour les modèles et les schemas

Marten offre désormais la possibilité de définir des champs `json` dans les [modèles](../../models-and-databases/reference/fields.md#json) et les [schemas](../../schemas/reference/fields.md#json). Ces champs vous permettent de persister et d'interagir facilement avec des structures JSON valides qui sont exposées comme des objets [`JSON::Any`](https://crystal-lang.org/api/JSON/Any.html) par défaut.

Par exemple :

```crystal
class MyModel < Marten::Model
  # Other fields...
  field :metadata, :json
end

MyModel.last!.metadata # => JSON::Any object
```

De plus, il est également possible de spécifier que les valeurs JSON doivent être désérialisées en utilisant une classe qui utilise [`JSON::Serializable`](https://crystal-lang.org/api/JSON/Serializable.html). Cela peut être réalisé en utilisant l'option `serializable` dans les [champs de modèle](../../models-and-databases/reference/fields.md#json) et les [champs de schema](../../schemas/reference/fields.md#serializable).

Par exemple :

```crystal
class MySerializable
  include JSON::Serializable

  property a : Int32 | Nil
  property b : String | Nil
end

class MyModel < Marten::Model
  # Other fields...
  field :metadata, :json, serializable: MySerializable
end

MyModel.last!.metadata # => MySerializable object
```

### Champ durée pour les modèles et les schemas

Il est désormais possible de définir des champs `duration` dans les [modèles](../../models-and-databases/reference/fields.md#duration) et les [schemas](../../schemas/reference/fields.md#duration). Ceux-ci vous permettent de persister facilement des durées valides (qui correspondent à des objets [`Time::Span`](https://crystal-lang.org/api/Time/Span.html) en Crystal) dans vos modèles mais aussi d'attendre des durées valides dans les données validées via l'utilisation de schemas.

Par exemple :

```crystal
class Recipe < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  # Other fields...
  field :fridge_time, :duration, blank: true, null: true
end
```

### Fonctionnalités mineures

#### Modèles et bases de données

* De nouvelles méthodes [`#get_or_create`](../../models-and-databases/reference/query-set.md#get_or_create) / [`#get_or_create!`](../../models-and-databases/reference/query-set.md#get_or_create-1) ont été ajoutées aux query sets afin de permettre de récupérer facilement un enregistrement de modèle correspondant à un ensemble de filtres donné ou d'en créer un nouveau si aucun enregistrement n'est trouvé.
* Les champs [`string`](../../models-and-databases/reference/fields.md#string) prennent désormais en charge une option `min_size` permettant de valider la taille minimale des valeurs de champs de type chaîne persistées.
* Une nouvelle méthode [`#includes?`](../../models-and-databases/reference/query-set.md#includes) a été ajoutée aux query sets afin d'effectuer facilement des vérifications d'appartenance sans charger la liste complète des enregistrements ciblés par un query set donné.
* Des méthodes [`#exists?`](../../models-and-databases/reference/query-set.md#exists) alternatives ont été ajoutées aux query sets afin de permettre de spécifier des filtres supplémentaires à utiliser dans le cadre des vérifications d'existence.
* Une méthode [`#any?`](pathname:///api/0.3/Marten/DB/Query/Set.html#any%3F-instance-method) a été ajoutée aux query sets afin de court-circuiter l'implémentation par défaut de [`Enumerable#any?`](https://crystal-lang.org/api/Enumerable.html#any%3F%3ABool-instance-method) et d'éviter de charger la liste complète des enregistrements en mémoire (lorsqu'elle est appelée sans arguments). Cette méthode surchargée est techniquement un alias de [`#exists?`](../../models-and-databases/reference/query-set.md#exists).
* Les migrations Marten sont désormais optimisées pour prévenir les possibles problèmes de dépendances circulaires au sein des tables ajoutées ou supprimées
* Il est désormais possible de définir des options de base de données arbitraires en utilisant le nouveau paramètre de base de données [`db.options`](../../development/reference/settings.md#options).
* Il est désormais possible de définir des champs [`many_to_one`](../../models-and-databases/reference/fields.md#many_to_one) et [`one_to_one`](../../models-and-databases/reference/fields.md#one_to_one) qui ciblent des modèles avec des champs de clé primaire non entiers (comme les champs UUID par exemple).

#### Handlers et HTTP

* Le handler générique [`Marten::Handlers::RecordList`](../../handlers-and-http/reference/generic-handlers.md#listing-records) offre désormais la possibilité de spécifier un [query set](../../models-and-databases/queries.md) personnalisé au lieu d'une classe de modèle. Cela peut être réalisé grâce à l'utilisation de la macro [`#queryset`](pathname:///api/0.3/Marten/Handlers/RecordListing.html#queryset(queryset)-macro).
* Un nouveau middleware [`Marten::Middleware::AssetServing`](../../handlers-and-http/reference/middlewares.md#asset-serving-middleware) a été introduit pour faciliter la distribution des assets collectés dans les situations où il n'est pas facile de configurer un serveur web (comme [Nginx](https://nginx.org)) ou un service tiers (comme Amazon S3 ou GCS) pour distribuer directement les assets.
* Un nouveau middleware [`Marten::Middleware::SSLRedirect`](../../handlers-and-http/reference/middlewares.md#ssl-redirect-middleware) a été introduit pour permettre de rediriger facilement les requêtes non-HTTPS vers HTTPS.
* Un nouveau middleware [`Marten::Middleware::ContentSecurityPolicy`](../../handlers-and-http/reference/middlewares.md#content-security-policy-middleware) a été introduit pour garantir la présence de l'en-tête Content-Security-Policy dans les en-têtes de la réponse. Veuillez consulter [Content Security Policy](../../security/content-security-policy.md) pour en savoir plus sur l'en-tête Content-Security-Policy et comment le configurer.
* Le middleware [`Marten::Middleware::I18n`](../../handlers-and-http/reference/middlewares.md#i18n-middleware) peut désormais déterminer automatiquement la locale actuelle en se basant sur la valeur d'un cookie dont le nom peut être configuré avec le paramètre [`i18n.locale_cookie_name`](../../development/reference/settings.md#locale_cookie_name).
* Le middleware [`Marten::Middleware::I18n`](../../handlers-and-http/reference/middlewares.md#i18n-middleware) définit désormais automatiquement l'en-tête Content-Language en fonction de la locale activée.

#### Templates

* Un filtre de template [`join`](../../templates/reference/filters.md#join) a été introduit pour permettre de convertir des valeurs de template énumérables en une chaîne séparée par une valeur de séparation.
* Un filtre de template [`split`](../../templates/reference/filters.md#split) a été introduit pour permettre de convertir une chaîne en un tableau d'éléments.

#### Schemas

* Des méthodes getter type-safe (c.-à-d. `#<field>`, `#<field>!` et `#<field>?`) sont désormais automatiquement générées pour les champs de schema. Veuillez consulter [Accéder aux données validées](../../schemas/introduction.md#accessing-validated-data) dans la documentation des schemas pour en savoir plus sur ces méthodes et comment/pourquoi les utiliser.

#### Développement

* Les exceptions [`Marten::HTTP::Errors::SuspiciousOperation`](pathname:///api/0.3/Marten/HTTP/Errors/SuspiciousOperation.html) sont désormais affichées via la page d'erreur interne de débogage pour faciliter le diagnostic d'erreurs telles que les erreurs d'hôte inattendu (qui résultent d'une valeur d'hôte manquante dans le paramètre [`allowed_hosts`](../../development/reference/settings.md#allowed_hosts)).
* [`Marten#setup`](pathname:///api/0.3/Marten.html#setup-class-method) lève désormais des exceptions [`Marten::Conf::Errors::InvalidConfiguration`](pathname:///api/0.3/Marten/Conf/Errors/InvalidConfiguration.html) lorsqu'une base de données configurée implique un backend qui n'est pas installé (par ex. une base de données MySQL configurée sans que `crystal-lang/crystal-mysql` ne soit installé et requis).
* La commande de gestion [`new`](../../development/reference/management-commands.md#new) crée désormais automatiquement un fichier [`.editorconfig`](https://editorconfig.org) pour les nouveaux projets.
* Un nouveau paramètre [`root_path`](../../development/reference/settings.md#root_path) a été introduit pour permettre de configurer l'emplacement réel des sources du projet dans votre système. Cela est particulièrement utile lors du déploiement de projets qui ont été compilés dans un emplacement différent de leur destination finale, ce qui peut arriver sur des plateformes comme Heroku. En définissant le chemin racine, vous pouvez vous assurer que votre application peut trouver toutes les sources de projet nécessaires, ainsi que d'autres fichiers comme les locales, les assets et les templates.
* Une nouvelle option `--plan` a été ajoutée à la commande de gestion [`migrate`](../../development/reference/management-commands.md#migrate) afin de fournir un aperçu complet des opérations qui seront effectuées par les migrations appliquées ou non appliquées.
* Un mode interactif a été ajouté à la commande de gestion [`new`](../../development/reference/management-commands.md#new) : si les arguments `type` et `name` ne sont pas fournis, la commande invite désormais l'utilisateur à saisir le type de structure, le nom de l'application ou du projet, et s'il faut générer l'application d'authentification.
* Il est désormais possible de spécifier des alias de commande lors de la définition de commandes de gestion en utilisant la méthode d'aide [`#command_aliases`](pathname:///api/0.3/Marten/CLI/Manage/Command/Base.html#command_aliases(*aliases%3AString|Symbol)-class-method).

#### Sécurité

* La possibilité de configurer et personnaliser entièrement l'en-tête Content-Security-Policy a été ajoutée au framework. Veuillez consulter [Content Security Policy](../../security/content-security-policy.md) pour en savoir plus sur l'en-tête Content-Security-Policy et comment le configurer dans les projets Marten.

#### Déploiement

* Un nouveau guide a été ajouté afin de documenter [comment déployer sur Heroku](../../deployment/how-to/deploy-to-heroku).
* Un nouveau guide a été ajouté afin de documenter [comment déployer sur Fly.io](../../deployment/how-to/deploy-to-fly-io).

## Changements rétro-incompatibles

### Handlers et HTTP

* Les [paramètres de route personnalisés](../../handlers-and-http/how-to/create-custom-route-parameters.md) doivent désormais implémenter une méthode [`#regex`](pathname:///api/0.3/Marten/Routing/Parameter/Base.html#regex%3ARegex-instance-method) et ne peuvent plus se fier à une macro `#regex` pour générer une telle méthode.
* Les handlers génériques qui nécessitaient l'utilisation d'une méthode de classe `#model` utilisent désormais une macro dédiée à la place. Cela permet de rendre les handlers qui héritent des classes de handlers génériques plus type-safe lors de la manipulation d'enregistrements de modèle.
* Les handlers génériques qui nécessitaient l'utilisation d'une méthode de classe `#schema` utilisent désormais une macro dédiée à la place. Cela permet de rendre les handlers qui héritent des classes de handlers génériques plus type-safe lors de la manipulation d'instances de schema.
