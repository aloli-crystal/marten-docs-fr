## Prérequis et compatibilité

* **Crystal :** 1.17, 1.18 et 1.19.
* **Bases de données :**
  * MariaDB 10.5 et supérieur.
  * MySQL 8.0.11 et supérieur.
  * PostgreSQL 14 et supérieur.
  * SQLite 3.31.0 et supérieur.

## Nouvelles fonctionnalités

### Relations polymorphiques

Les relations polymorphiques peuvent désormais être définies grâce à l'utilisation de champs [`polymorphic`](../../models-and-databases/reference/fields.md#polymorphic). Ceux-ci sont utiles lorsque vous souhaitez stocker une référence à un enregistrement dont le modèle peut varier parmi un ensemble prédéfini de types possibles.

Par exemple :

```crystal
class Article < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :title, :string, max_size: 128
end

class Recipe < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  field :title, :string, max_size: 128
end

class Comment < Marten::Model
  field :id, :big_int, primary_key: true, auto: true
  // highlight-next-line
  field :target, :polymorphic, to: [Article, Recipe], related: :comments
  field :text, :text
end
```

Dans l'exemple ci-dessus, un enregistrement `Comment` pourrait être associé à un enregistrement `Article` ou `Recipe`, et chacun de ces modèles pourrait avoir de nombreux enregistrements `Comment` associés.

Des méthodes d'aide et des scopes pratiques sont également générés pour les champs polymorphiques, permettant d'interagir avec les enregistrements liés de manière type-safe. Par exemple :

```crystal
# Create an article
article = Article.create!(title: "This is an article")

# Create a recipe
recipe = Recipe.create!(title: "This is a recipe")

# Create a comment
comment = Comment.create!(text: "This is a comment", target: article)

# Regular getter methods
comment.target      # => #<Article:0x1036e3ee0 id: 1, title: "This is an article">
comment.target_type # => "Article"
comment.target_id   # => 1

# Type class getter method
comment.target_class  # => Article (or nil if no related record is set)
comment.target_class! # => Article (or raise if no related record is set)

# Predicate helper methods
comment.article_target? # => true
comment.recipe_target?  # => false

# Typed getters methods
comment.article_target  # => Returns the associated Recipe record if the targeted record is indeed a Recipe record (or nil otherwise)
comment.article_target! # => Returns the associated Recipe record if the targeted record is indeed a Recipe record (or raise otherwise)

# Type-specific model scopes (generated based on the specified type classes)
Comment.with_article_target # => Returns all the comments associated with Article records
Comment.with_recipe_target  # => Returns all the comments associated with Recipe records
```

Veuillez consulter [Relations polymorphiques](../../models-and-databases/relationships.md) pour en savoir plus sur cette nouvelle capacité.

### Fonctionnalités mineures

#### Modèles et bases de données

* Les query sets fournissent désormais une méthode [`#limit`](../../models-and-databases/reference/query-set.md#limit) et une méthode [`#offset`](../../models-and-databases/reference/query-set.md#offset). Ces méthodes permettent respectivement de limiter le nombre d'enregistrements retournés et de décaler les enregistrements retournés. Elles agissent comme des alias pour la [méthode `#[]` avec un range](../../models-and-databases/reference/query-set.md#range).
* La méthode de query set [`#update`](../../models-and-databases/reference/query-set.md#update) peut désormais être appelée directement sur les classes de modèle, permettant ainsi de mettre à jour tous les enregistrements du modèle considéré avec les valeurs spécifiées.
* Il est désormais possible de mettre à jour uniquement des colonnes spécifiques sans exécuter de validations ou de callbacks pour un enregistrement de modèle en utilisant la méthode [`#update_columns`](../../models-and-databases/introduction.md#updating-specific-columns).
* Il est désormais possible de créer ou mettre à jour facilement des enregistrements en un seul appel en utilisant la méthode de query set [`#update_or_create`](../../models-and-databases/reference/query-set.md#update_or_create). Une variante [`#update_or_create!`](../../models-and-databases/reference/query-set.md#update_or_create-1) est également disponible dans le même but, mais elle lève une exception si les enregistrements mis à jour/créés sont invalides.

#### Handlers et HTTP

* Les objets [`Marten::HTTP::UploadedFile`](pathname:///api/dev/Marten/HTTP/UploadedFile.html) peuvent désormais être sérialisés en JSON.
* Une méthode pratique [`#remote_ip_address`](pathname:///api/dev/Marten/HTTP/Request.html#remote_ip_address%3AString|Nil-instance-method) a été ajoutée à la classe [`Marten::HTTP::Request`](pathname:///api/dev/Marten/HTTP/Request.html), permettant de récupérer facilement l'adresse IP distante de la requête entrante.

#### Templates

* La plupart des propriétés informationnelles de chaîne (comme `#ascii_only?`, `#blank?`, `#bytesize`, `#empty?`, `#size` et `#valid_encoding?`) sont désormais disponibles en tant qu'attributs de template pour les valeurs de chaîne et les [valeurs de chaîne sûres](../../templates/introduction.md#auto-escaping).

#### Développement

* Le [store flash](../../handlers-and-http/introduction.md#using-the-flash-store) peut désormais être accédé depuis le client de spec en utilisant la méthode [`#flash`](pathname:///api/dev/Marten/Spec/Client.html#flash-instance-method). Consultez [Messages flash](../../development/testing.md#flash-messages) pour plus de détails.
* La possibilité de lier le serveur à un socket Unix a été introduite en ajoutant un nouveau paramètre [`socket`](../../development/reference/settings.md#socket).
